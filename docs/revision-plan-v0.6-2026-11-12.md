# 修改方案 v0.6（2026-11-12）

依据：对 v0.5.0-rc.1 的可玩性 / 前端 UI / 剧情 / 创意四角度评审。本文含剧透。
前置条件：v0.5 修订（docs/revision-plan-2026-11-12.md）全部 P0–P4 项已完成，仅剩 3 名陌生玩家试玩未组织。

## 0. 不动的原则

沿用 v0.3–v0.5 的五条原则，任何改动与之冲突以这里为准：

- **证据门**是核心资产：推进必须由玩家拿出的证据支撑，不靠排除法。
- **原始记录稳定**：已保存的照片、录像、文档永不变化；变化只发生在现场回传、关联预览和外部世界（论坛）。
- **不触碰现实信息**：不读摄像头、麦克风、地理位置、本机文件、真实用户名。所有"它在看你"的效果只用浏览器内部状态，刷新即恢复。
- **无突脸**：最强刺激是 ≤100ms 的一帧异常和文字。
- **错误可恢复**：不设真实倒计时，不设永久失败。

新增两条本方案专属约束：

- **daedalOS 上游可更新**：桌面层改动优先用 CSS 变量与新增覆盖文件，不直接改上游组件逻辑；必须改上游文件时在 DAEDALOS.md 登记。
- **辅助功能不强制**：所有新增的恐怖/氛围效果提供"关闭氛围效果"开关；所有依赖听力或反应速度的机制必须有视觉等价物。

## 阶段 A　可玩性修正（约 3 天）

### A1 第 2 关（核对外墙）"伪通过"陷阱

**问题**：当前玩家出示户型图西墙 + 外墙照片即通过，不训练"看元数据"的习惯，而这个习惯是 R-03 实验记录（三组对照）的前置能力。

**改动**：

1. `content.js` 的 `exterior` 文档拆为两条：
   - `exterior-2018`：现有修缮公告，保留。figcaption 标注"2018.06 修缮前存档"。
   - `exterior-2026`：新增物业公告页"二号楼例行巡检留影（2026.03）"，含一张外观几乎相同的照片 `assets/exterior-2026.png`，但墙面有 2026 年检修标签、空调外机位置不同。
2. 第 2 关 `cite.need` 判定改为：必须出示**户型图西墙** + **两张外墙照片中的任意一张**，但引擎额外记录玩家出示了哪张。
3. 若玩家只出示了 `exterior-2026`（或两张都出但 2018 那张未读），陆遥回复：
   > 物业说这是今年三月巡检拍的。……可我朋友住那儿的时候，空调外机不在这个位置。你再看一眼旧的那张？
   
   不卡关，但把"日期是证据的一部分"这条规则用事实而非教学说出。
4. 提示体系接入：第二次错误后 hint 指向 figcaption 的日期。

**验收**：`tests/engine.test.js` 新增用例——只出示 2026 照片时 stage 不推进且触发上述台词；两张都读后正常推进。

### A2 第 8 关（杯子测试）量帧辅助

**问题**：2 秒量帧对缺乏耐心的玩家是流失点，但直接自动标帧会消解"自己发现"的恐怖感。

**改动**：

1. 量帧界面新增"标出可疑帧"按钮，常驻可见。
2. 点击消耗 **1 次提示计数**（计入 PLAYTEST.md 的"提示次数"统计），然后在时间轴上以灰框标出含异常手部的前后 10 帧区间，**仍需玩家自己拖动到区间内确认**。
3. 按钮文案中性："帮我缩小范围"。不出现"答案""作弊"字样。

**验收**：点击后 hint 计数 +1，灰框渲染正确；玩家仍须完成出示手部帧的动作才能推进。

### A3 救援关触觉反馈可视化

**问题**：方向键 + 简化模式已有，但"摸到绳结"缺乏不依赖音频的确认信号，静音玩家只能靠文本提示。

**改动**（`dist/rescue.js` + 新增 `rescue-tactile.css`）：

1. 救援界面底部新增一条横向触觉波形带（`<canvas>` 高约 48px）：
   - 平段为低幅噪波（模拟手掌摩擦绳面）。
   - 经过单结时波形凸起一次，双结凸起两次，蓝胶布段波形变为规则的密集小峰。
   - 墙缝压绳段波形被"压平"，缝张开瞬间波形弹起。
2. 波形与现有低频绳结声严格同步（同一时钟源），声音关闭时波形照常工作。
3. 简化模式下波形带自动放大为 96px，并在结点上叠加文字标签（"单结""双结""胶布"）。

**验收**：Playwright 脚本静音跑通救援全程，仅依据 DOM 中波形 canvas 的状态断言（暴露 `data-tactile="knot|double|tape|pinched"` 供测试）。

### A4 章节选择界面

**问题**：90–120 分钟流程无中途续玩引导，存档迁移只对老玩家有意义，对新玩家是黑盒。

**改动**：

1. 入口帖"打开镜像"进入桌面后，若检测到已有存档（stage > 0），聊天窗口首条消息变为陆遥的"接着上次"摘要（自动列出已达成的 12 节点中最后一个的名称）。
2. 调查便签新增"进展"页：12 节点以时间线列出，已完成节点可点击，点击后**重放该节点的关键证据列表**（不是跳过，是回顾）。不允许跳到未完成节点。
3. 存档 `version` 升到 3，`hydrate` 处理 v2→v3（新增字段给默认值）。

**验收**：v2 存档载入后 stage 与证物栏无损；新玩家无存档时不显示进展页入口以外的任何剧透。

## 阶段 B　前端 UI（约 3 天）

### B1 全局"深夜工作机"色调

**改动**（新增 `desktop/public/case/case-theme.css`，由集成脚本注入各 case 应用；daedalOS 桌面层只改 CSS 变量）：

1. 桌面壁纸叠加 `rgba(16, 18, 30, 0.05)` 的冷色层（纯 CSS `::before`，不动壁纸文件）。
2. 窗口非激活标题栏亮度降 8%，激活窗口保持原样——让玩家的注意力锚点始终是"正在操作的窗口"。
3. 全部变量化：`--case-tint`、`--case-titlebar-dim`，上游更新时只需保留这一个文件。

**验收**：截图对比激活/非激活窗口标题栏；`desktop/` 上游组件零逻辑改动（`git diff` 仅变量文件与集成点）。

### B2 HC_ARCHIVE 文件管理器的"证物视角"

**改动**（daedalOS 文件管理器的目录级定制，尽量通过其现有 theme/extension 点实现；实现不了的最小集直接 patch 上游文件并登记）：

1. HC_ARCHIVE 及其子目录内，文件图标按类型替换为"证物袋"样式：
   - 照片/录像：透明袋 + 白标签 + 编号角标。
   - 文档：牛皮纸档案袋。
   - 快捷方式保持原生样式（区分"系统入口"与"证物"）。
2. 该目录内右键菜单新增"标记为线索 / 取消标记"：
   - 状态写入 IndexedDB（key: `marked:{fileId}`），与证物栏共用存储事件同步。
   - 已标记文件图标右上角红色圆点。
3. 状态栏在该目录下显示"已标记 N 条线索"，替代默认的"N 个项目"。
4. 目录外（我的电脑等）一切行为保持原生，防止破坏 daedalOS 通用性。

**验收**：标记在刷新、关窗、重开游戏后保留；目录外右键菜单无新增项；汉化条目风格与 v0.5 汉化一致。

### B3 聊天窗口的压迫感递进

**改动**（CaseChat 应用内，全部基于现有 stage 状态驱动）：

1. **头像退化**：stage ≥ 6 陆遥头像饱和度 -40%；stage ≥ 9 再叠加轻微噪点（CSS filter + SVG noise，不换头像文件）。
2. **输入状态焦虑化**：stage ≥ 9 时，"正在输入…"出现频率提高、实际消息到达延迟 ±3s 随机化，但**总信息量和到达顺序不变**——只改变等待体验，不改变证据时序（避免违反证据公平性）。
3. 气泡样式、字号、行距不动（保持工作工具的朴素）。
4. 上述效果受"关闭氛围效果"开关控制，关闭后聊天回到 v0.5 行为。

**验收**：开关切换即时生效；stage ≥ 9 下消息顺序与内容与 v0.5 逐条一致（diff 测试）。

### B4 空间复核工具的"专业仪器感"

**改动**（CaseSpace 应用内）：

1. 覆盖图区域改深蓝网格底（CSS 渐变网格，无图片资源），已注册视点为发光圆点，缺口方向为虚线弧。
2. "激活关联"改为拟物拨杆开关：拨动播放一次"咔哒"采样（≤0.3s，默认音量 30%，可静音），状态由开关位置而非仅颜色表达（色盲友好：开=右+亮，关=左+暗）。
3. "补齐覆盖"确认弹窗改为系统警告样式：黄色三角图标、正文明确列出"将闭合的方向数"和"受影响的活动终端数"，主按钮文案为"我仍然要补齐"（主动语态，强化这是玩家的选择），次按钮"先不动"。
4. 弹窗 UI 不预设倒计时，不自动选择。

**验收**：拨杆状态与引擎 `paused` 状态双向同步；补齐确认的两步（展示影响 → 二次确认）在自动化脚本中可分别断言。

## 阶段 C　剧情增补（约 1.5 天，纯内容为主）

### C1 陆遥的日常痕迹前置

**改动**：

1. 开场桌面新增便签"周五前"（普通便签文件，非证物）：
   > 陆遥的房租尾款 800，周五前结。
   > 她说松亭的采光适合拍新一期的片子。
2. 入口帖 #8 陆遥楼层已存在（v0.5 加的 POV 闭合），在其后补一句：
   > 对了，尾款等我回来就结，别催。

**验收**：便签不计入证物栏、不被搜索索引为线索关键词（避免干扰"寻找房屋"的搜索测试）。

### C2 杯子测试录像的环境音

**改动**：

1. 录像音轨混入极低电平（-28dB）的 2019 年综艺风格背景电视声（自制合成，避免版权素材；用 Tone.js 生成模拟人声节目的节奏噪声即可），从放下杯子后第 3 秒进入，持续 6 秒后淡出。
2. 字幕轨同步标注"[远处电视声]"，保证静音玩家获得同等信息。
3. 该声音在"对面手动"出现的时刻**不停**——正常生活声与异常动作叠在一起是设计意图。

**验收**：音轨峰值不超过 -12dB；字幕与音频时间轴对齐误差 <200ms。

### C3 沈屹手簿撕页

**改动**：

1. `manual` 文档末尾新增一段（独立 `<p data-cite="manual:torn">`）：
   > （下一页被撕掉了。纸茬上留着半行字：）
   > 「如果那天我先问了她怕不——」
2. 该句**可引用但不属于任何关卡的 need 组**——它是人物线证据，不是通关证据；出示给陆遥时她回一句固定台词：
   > ……他后来每年 11 月都去松亭。物业的人说的。

**验收**：出示该句不推进 stage、不记错误次数；台词只出现一次。

### C4 结局余味分层

**改动**：

1. **safe 结局追加**：陆遥"先别挂，我走到路口再说"之后，聊天窗口自动最小化，桌面时钟跳到 23:47。玩家可自由继续翻文件（此时 `trace` 照片可重新查看），或从开始菜单关机（播关机画面，游戏结束）。**不新增异常**。
2. **safe-marked 结局**：在 safe 的基础上，玩家任意时刻回到论坛标签页时，帖子多出一楼（DOM 追加，复用 v0.5 的活帖子机制）：
   > **hc_tmp_041**（注册 2019-11-22，帖子 2）：门楔动了。
3. 该楼层只在达成 safe-marked 后写入论坛的持久状态，未达成时永不出现。

**验收**：safe 与 safe-marked 的论坛 DOM diff 仅这一楼；未通关存档访问论坛无此楼。

## 阶段 D　创意层（约 2.5 天，全部可开关）

### D1 浏览器内的"安全破墙"

**改动**（全部限定在 case 应用与当前标签页，刷新即恢复）：

1. **任务栏时钟倒转**：首次激活异常关联后，任务栏时钟 CSS 动画倒走 5 秒（不改真实时间源，动画结束后恢复正常走字）。每次会话最多触发一次。
2. **异常项目的时间列**：HC_ARCHIVE 内异常项目目录的文件，"修改日期"列显示"昨天 / 刚才 / 现在"（按文件固定映射，不随机），目录外不受影响。

**验收**：Date 对象与系统时间全程未被修改（测试断言 `Date.now()` 单调）；刷新页面后一切恢复。

### D2 "芦苇搜索"的图片搜索

**改动**：

1. 搜索结果页新增"图片"标签，默认空态文案"没有找到相关图片"。
2. 唯一例外：搜索词同时含"松亭"与"窗"时，返回 1 条结果——玩家**本次会话中最近一次打开过的** `room` 照片的缩略图（从 IndexedDB 读会话状态，不上传、不存储到任何持久位置），标注"相似图片 · 1 小时前"。
3. 该结果不可点击放大（只给缩略图），点击提示"源文件不可用"。

**验收**：无痕新会话首次搜索不返回该结果（尚无打开记录）；打开过照片后搜索才出现；清空会话存储后消失。

### D3 声道的空间错乱

**改动**（`dist/sound.js`）：

1. stage ≥ 7 且玩家把任一窗口拖到视口左半区时，下一次环境声（拖椅子/旧电话采样）的声像反相到右侧（Web Audio `StereoPannerNode`，pan 值与窗口位置取反）。
2. 效果概率 40%，同一环境声不重复反相，避免变成可预期的 gimmick。
3. 受"关闭氛围效果"开关控制；单声道输出设备上自动禁用（检测 `channelCount`）。

**验收**：自动化测试注入窗口位置后断言 panner 值；开关关闭时 pan 恒为 0。

### D4 二周目"沈屹模式"（可选，v0.6 可裁剪项）

**改动**：

1. 通关任意结局后，开始菜单出现"HC-19-041 · 原始项目"入口。
2. 进入后是 CaseSpace 的只读变体：玩家以沈屹视角浏览 2019 年项目，覆盖图为当年状态；陆遥聊天替换为沈屹备忘录（复用聊天 UI，消息来源改为 `shen-memo`），节点顺序按 2019 年时间线重排。
3. **不新增谜题、不新增结局**——纯粹是同一批证据的另一条时间线视角，服务核心玩家复拼时间线。

**验收**：该模式不写入任何主线存档字段；未通关时不出现入口。

**裁剪说明**：若 v0.6 排期紧张，D4 整体可延后至 v0.7，不影响其他项。

## 验收总表（新增到 PLAYTEST.md 复盘重点）

- 玩家是否注意到外墙照片日期差异，还是被提示后才回头。
- 量帧辅助按钮的使用率与使用后仍完成确认的比例。
- 静音玩家仅凭触觉波形能否完成救援。
- 聊天退化是否被玩家归因于"信号/她的状态"而非"游戏 bug"（复盘提问）。
- 图片搜索结果是否被玩家发现，发现后的第一反应（记录原话）。
- 时钟倒转是否有玩家注意到；注意到的人是否认为与剧情有关。
- 所有氛围开关关闭后，主线是否仍可 100% 通关（自动化回归）。

自动化回归 + 本方案全部 P0/P1 完成后，再组织 PLAYTEST.md 的 3 名陌生玩家试玩，试玩版本号记为 v0.6.0-rc.1。
