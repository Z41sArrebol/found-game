# 叙事形式扩展与路线重排（取代原 P0–P3 线性清单）

2026-11-12。背景：对标《寻找陈雨彤》后确认了"整个网页就是游戏"的做法可行；用户提出两个方向——①电脑不变，电脑内做一个 寻找陈雨彤 式静态论坛；②网页为主体，电脑只在特定情节出现。本文把两个点子接住，再往外推，给出新路线。

## 一个核心洞察：我们的故事天然适合"双端结构"

游戏的主题是**远端与现场**——许澄在远端查资料，陆遥在现场冒险；"补齐覆盖会把远端操作者也纳入定位"是故事的底层规则。那么叙事形式本身就应该复现这个结构：

- **桌面 = 现场/远端操作台**（玩家正在用的）。
- **一个普通网页 = 外部世界**（论坛、博客、物业公告——围观者的地方）。

两者可以做成同一个静态站里的两页，用 localStorage 同步进度。玩家开两个标签页：一边查硬盘，一边看着"外部世界"的帖子随剧情更新。远端/现场的恐怖关系，被浏览器标签页这个日常形式自己演出来了。这是比"换皮"更深的一层。

## 形式清单（从两个点子出发）

### 1. 入口反转：论坛作为第一屏（点子②，落地冷启动的最终形态）

游戏网址 `/forum` 打开的是一个 2026 年的「芦苇社区」帖子，不是游戏菜单：

- 楼主陆遥：【求助】朋友失联前住的房间，2019 年的照片最近"不对劲"。正文交代硬盘的来历，回帖有人说是 PS、有人劝她报警、有人说"这楼的户型图我好像见过"。
- 帖内一个附件链接：「硬盘镜像（她寄我的那份）」。点它，页面跳转到桌面，冷启动开始。全程没有"接入硬盘"按钮。
- 其余帖子全部死链（渲染成链接但点不动），页脚一句"旧站已转为只读"，寻找陈雨彤 式纹理。
- 这个页面同时是传播入口：实况切片、发给朋友的最短链接。手机打开也该能读（一份 CSS 的事）。

POV 是顺的：这个帖子就是许澄接活之前看到的那一帖，玩家读帖=代入许澄的第一天。

### 2. 电脑内的静态网页宇宙（点子①）

芦苇搜索能搜到的不再只是"资料卡片"，而是真正打开的**站内网页**（阅读器/浏览器面板渲染）：

- 2019 年论坛存档帖：【求助】寻找青苇工作间的陈苇——她失联前最后回复是在几号楼拍照。回帖有气氛回复、有死链干扰帖，只有关键楼层挂着下一个线索（她的博客、衡川官网）。
- 陈苇的博客：2019 年冻在半句的最后一篇。
- 衡川测绘公司官网：团队页里沈屹的照片、项目列表里 HC-19-041 一栏"已归档"。
- 全部静态、只读、刷新无效；每个站只有能推进剧情的链接是活的。

### 3. 活的帖子（双标签页叙事，本文第一节的落点）

论坛页读 localStorage 里的存档进度，随 12 个节点长出新楼层：

- 开局：只有陆遥的求助帖。
- 第 6 节后：陆遥更新"我进去了，信号不好"，楼下开始有人劝她出来。
- 第 7 节后：她失联。物业账号现身回复"该户查无此人"。许澄的账号顶帖求线索。
- 结局分支：safe/stop/bad 各有不同末楼；bad 结局那栋楼里，有人回了一句"楼主，你的电脑是不是也开了这个页面"。

技术上只是 `storage` 事件+按 stage 渲染楼层，零风险。玩家可以把论坛标签页一直开着——**外界在实时围观这场调查**，这是任何全屏游戏给不了的体感。

### 4. 陈苇的博客 / 衡川官网 / 物业公告（低成本的站点家族）

同一条「旧站已转为只读」规则下的三个静态小站，各自只承担一两个线索点。复用同一个论坛模板，内容就是 content.js 里的新文档。

### 5. 声音与微惊吓（并入）

- 论坛页打开时极轻的电流底噪；关联活动中桌面低频嗡鸣（WebAudio 合成，无音频资产，默认可关）。
- 恢复关联瞬间一帧异常图（≤100ms）。
- 论坛页"刷新无效"：刷新后楼层顺序看起来没变，但某楼的时间戳快了几分钟——留给细心的玩家。

### 6. 传播件

- 结局回执卡（结局+用时+已读材料数+重探提示）。
- 入口论坛帖本身就是 teaser：切片、转发、入坑三合一。

## 新落地顺序（替换原 P0–P3）

| 阶段 | 内容 | 工作量 | 备注 |
|---|---|---|---|
| R1 | `/forum` 入口帖 + 桌面冷启动（删 landing） | 小 | 一个静态页 + 删一个函数；杠杆最大 |
| R2 | 站内网页宇宙：论坛模板 + 陈苇帖/博客/衡川官网 | 中 | 复用模板，主要是写内容 |
| R3 | 活帖子：论坛随 stage 长楼层、结局分支末楼 | 小–中 | storage 事件 + stage 渲染 |
| R4 | 声音层 + 微惊吓 | 中 | WebAudio 合成，无资产 |
| R5 | 结局回执卡 | 小 | 实况切片友好 |

R1/R2/R3 是同一个"双端叙事"的三步，建议按序做；R4/R5 可并行插空。

## 待定（需拍板）

1. 入口帖的文案与论坛品牌名（建议「芦苇社区」，与芦苇搜索同门面；帖子正文我按陆遥的口吻起草后给用户过目）。
2. R3 的 bad 结局末楼尺度——"对玩家说话"到哪一层（建议只到"注意到"，不点名现实信息，守住设定里"它无法知道玩家现实生活"的规则边界）。

## 补充机制（2026-11-12 第二批，来自参考案例 青苗中学/404-ymail）

### 7. 聊天输入解题（对话框即解谜界面）

参考做法：陆遥式的 NPC 在聊天里直接要一个具体信息，输入框占位文本同步引导（"把楼栋号发给她…"），答案不给——玩家自己去贴纸、邮件、日志里找，打字回复。答对推进剧情，答错 NPC 在角色内回应，无惩罚可重试。

适配性：这正是证据门哲学的另一种呈现——判断题考推理，输入题考检索。与设计稿"不靠重复输密码"不冲突（输入的是查证所得的事实，非密码墙）。

落地设计：

- 引擎：`puzzles[].input = {accept:[归一化串], askText, placeholder, wrong:[角色内反馈]}`；`resolve` 前置输入门，答错进 `wrong` 文案轮换，两次错误后接现有 hint 体系。
- 归一化：NFKC + 去空格 + 单位归一（"二号楼"/"2号楼"/"2 号楼"全收）；纯格式错误给灰字系统分隔线提示（wx-sys）。
- 候选节点（不全改，每章保留判断题骨架，全游戏插 2–3 处）：
  - S1 楼栋：贴纸+转租帖 → 输入"二号楼"（陆遥："对，二号楼。户型找二号的。"）
  - S9 距离：R-03 与绳结记录 → 输入"五米/5米"（陆遥报数的紧张感最强）
  - S10 密码：R-03 加密件，密码藏修订记录（陈苇的论坛 ID 或修订号）——解锁后才能看撤回方法，全游戏唯一一次密码门。
- 占位符动态化：默认"输入消息，回车发送"；陆遥最后一条以问号结尾 → "回复她…"；输入题激活 → 按 askText（"把楼栋号发给她…"）。

### 8. 正在输入状态行

消息流内的三点气泡已有；补一条对齐参考案例的**输入区状态行**："陆遥正在输入 ●●●"（dock 底部，灰色小字），跨面板广播复用现有 TYPE_KEY。两处并存：流内气泡指示落点，状态行指示存在感。

### 9. 站内 webmail（归入 R2 站点家族）

参考案例的假邮箱站（信箱列表+阅读窗+内嵌聊天存档）验证了 webmail 是高沉浸低成本的形态。落地：青苇工作间的「邮件导出」文档升级为站内 webmail 页（文件夹列表/邮件/阅读窗），沈屹与陈苇的往来信件作为独立邮件展开，比现在的一整页 doc 更有"翻别人邮箱"的体感。
